## Context

`changekit` is taken on npm by an unrelated package, last published in 2022,
so the name this project uses cannot carry the package this project needs to
publish. Installation today is `npx github:allan-lancioni/changekit`, which
asks a user to know an owner and a repository before they can try anything,
and the update check answers one question over two hosts and two protocols:
`git ls-remote --tags` for the latest version, then `raw.githubusercontent`
for the changelog that says what updating costs. 1.0.0 has never been tagged,
never reached `main` and never reached a registry, so the name and the channel
can both still move without costing anybody a migration.

## Goal

When this closes:

- `npx changepack` copies the skill into `.claude/skills/changepack/` in the
  repository it is run in, with nothing else to know and nothing to install.
- The npm registry is the only place a version is resolved from. One request
  answers both what the latest version is and what each release between it and
  the installed one costs.
- The skill, the configuration file, the command, the frontmatter key, the
  marker and the repository all read `changepack`.
- A push to `main` tags and publishes, so neither depends on somebody
  remembering.

## Changes

The tree of what moves, `+` added, `-` removed, `~` changed:

```text
.
├── ~ package.json           name, bin, files, publishConfig, changepack.updating
├── ~ README.md              npx changepack, and the box it describes
├── ~ CHANGELOG.md           the unreleased 1.0.0 entry gains this
├── ~ RATIONALE.md           the refusal of an npm package is rewritten
├── - CHANGEKIT.md           becomes ↓
├── + CHANGEPACK.md          the configuration this repository runs under
├── ~ scripts/check.mjs      the loaded path, and a fifth invariant
├── .github/workflows/
│   ├── - tag.yml            becomes ↓
│   └── + release.yml        tag and publish, on push to main
├── bin/
│   └── ~ install.mjs        the target directory, and every line it prints
└── skill/
    ├── ~ SKILL.md           name, the command, the marker
    ├── ~ check-update.mjs   one request, to the registry
    ├── references/
    │   ├── ~ init.md        writes CHANGEPACK.md, stamps changepack:
    │   ├── ~ update.md      installs npx changepack@<version> --force
    │   ├── ~ close.md       the path to the check
    │   ├── ~ run.md         the path to the check, CHANGEPACK.md
    │   ├── ~ work.md        the path to the check
    │   ├── ~ plan.md        the frontmatter key
    │   └── ~ commit.md      CHANGEPACK.md
    └── templates/
        ├── - changekit.md   becomes ↓
        ├── + changepack.md  the configuration template
        └── ~ change.md      the frontmatter key
```

`.claude/skills/changekit/` becomes `.claude/skills/changepack/`. It is
generated by the installer and is not edited by hand here.

What each name becomes:

| Today | After |
|---|---|
| `changekit` on npm, held by somebody else since 2018 | `changepack`, published from this repository |
| `npx github:allan-lancioni/changekit` | `npx changepack` |
| `npx github:allan-lancioni/changekit#<ref> --force` | `npx changepack@<version> --force` |
| `.claude/skills/changekit/` | `.claude/skills/changepack/` |
| `CHANGEKIT.md` | `CHANGEPACK.md` |
| `/changekit` | `/changepack` |
| `<!-- changekit 1.0.0 -->` | `<!-- changepack 1.0.0 -->` |
| `changekit:` in the config and in package frontmatter | `changepack:` |
| `github.com/allan-lancioni/changekit` | `github.com/allan-lancioni/changepack` |

What the update check does, today:

```text
close.md → check-update.mjs
             → git ls-remote --tags github.com/…       the latest tag
             → GET raw.githubusercontent/…/CHANGELOG   the Updating: lines
             → prints the version and the cost
```

and after:

```text
close.md → check-update.mjs
             → GET registry.npmjs.org/changepack       every version, each
                                                       carrying its own cost
             → prints the version and the cost
```

The cost line moves into the published manifest because the registry already
returns every version's `package.json` in one document. Reading the changelog
over a second host was the only reason the check needed a ref at all, and a
ref is what made it depend on a tag existing. A `changepack.updating` field,
generated from `CHANGELOG.md` at release and checked by `scripts/check.mjs`,
collapses two requests into one and removes git from a script that never
needed it. The changelog stays the document a person reads; the field is the
same sentence, addressed to a machine.

`tag.yml` becomes `release.yml` rather than gaining a step, because what it
guarantees changes. Tagging was idempotent and safe to re-run on every push;
publishing is not, and the workflow has to check the registry before it acts
rather than checking the remote for a tag.

## Decided

**The 1.0.0 already in `dev` stays.** Every reference to the version lives in
the 24 commits `dev` holds and `origin` does not, and no tag carries it, so
rewriting them was available and cheap. It is not worth doing: the changelog
already treats 1.0.0 as an entry that accumulates, three packages have amended
it rather than opened a version, and `refs/pull/2/head` keeps the number
public on GitHub whatever `dev` says. Rewriting would have bought a tidier log
and left the archive citing a version the log denied.

**The cost of updating is published with the package.** The alternative was to
keep fetching `CHANGELOG.md` from GitHub at a tag, which costs one more host,
one more protocol and the tag the whole change is trying to stop depending on.

**The GitHub repository is renamed too.** The alternative, keeping `changekit`
on the forge, costs a permanent discrepancy between the repository and
everything inside it. GitHub redirects the old path, so existing clones and
any `npx github:` still in the wild keep resolving.

**The installer does nothing about an existing changekit install.** It
installs `changepack` and leaves `.claude/skills/changekit/` and
`CHANGEKIT.md` where they are. The alternatives were to move them, which costs
the invariant that the installer never writes the file the project owns, or to
detect and instruct, which costs code in `bin/` that is dead after one
release. The cost accepted is that a repository that installed 0.7.0 has two
skill directories until somebody deletes one, and the changelog carries that
instruction rather than the installer.

## Scope

- The rename, across the source, the skill, the templates, the scripts, the
  installer, the workflow and the documents.
- Publishing to npm, and the workflow that does it.
- The update check reading the registry, and the field it reads.
- The fifth invariant in `scripts/check.mjs`: the published cost agrees with
  the changelog.
- Rewriting the refusal of an npm package in `RATIONALE.md`.

Out of scope:

- `changes/archive/`. Twelve files name changekit 65 times and they are the
  record of packages that closed under that name. The changelog already says
  archived packages are not migrated.
- The `v0.5.0` tag and the two closed pull requests. History on the forge is
  not rewritten.
- Any migration path for a repository running 0.7.0, beyond the line the
  changelog carries.

## Cost

- **Keeps working:** every repository already running changekit, which keeps
  the skill it has and is never contacted. Nothing installed reaches for the
  new name on its own, because `check-update.mjs` as installed still resolves
  `changekit` on GitHub and will keep reporting silence.
- **A revert does not undo:** the publication. Once `changepack@1.0.0` is on
  the registry it cannot be unpublished after 72 hours and the name is held
  from then on. Reverting this package returns the source to `changekit` and
  leaves a published `changepack` standing, so the last group is the one to
  stop at if anything is unsettled.

## Success criteria

- `npx changepack` in a clean repository writes `.claude/skills/changepack/`
  and nothing else, and prints the next step.
- `npm run check` passes, including the new invariant, with no occurrence of
  `changekit` outside `changes/archive/` and `CHANGELOG.md` history.
- `check-update.mjs` run against a stale `CHANGEPACK.md` prints the newer
  version and its cost line, using one network request and no `git`.
- The same script prints nothing when the installed version is current, when
  the network is unavailable, and when `updates:` is `off`.
- A push to `main` results in a `v1.0.0` tag and `changepack@1.0.0` on the
  registry, neither performed by hand.
